Deckster
Turn a spare phone into a wireless audio mixer for your Windows PC.
A plain-language manual: what Deckster does, how the pieces fit together, and enough of the architecture to use it confidently — or fork it.
Per-app volume & mute Microphone control Device switching Now-playing transport USB or Wi-Fi No extra hardware

Deckster is a free, no-hardware alternative to a Stream Deck or GoXLR. A tiny program (the agent) runs on your Windows PC and serves a touch app to your phone. Your phone becomes the mixer: one tile per application, a jog dial for volume, a mic button, device pickers, and media controls — for streamers, gamers, or anyone who wants their audio controls off the desktop and under their thumb.

The one-sentence version

Your phone shows a touch mixer; the PC agent applies what you touch to Windows audio in real time, and streams the current state back so the phone always matches the PC.

What Deckster does

Everything you control lives on the phone as a touch surface. The headline capabilities:

  • Per-app volume & mute — a tile for each app that is playing sound (your voice chat, browser, music, game), showing the real Windows app icon. Drag the jog dial to set a level.
  • Microphone — a one-tap mic mute that is always in reach, plus mic sensitivity.
  • Per-app mic mute — Windows cannot mute one app's microphone on its own, so Deckster fires that app's own mute / push-to-talk hotkey for you.
  • Output / input switching — pick speakers/headset and microphone from the phone, with live signal meters so you can see what is active.
  • Now playing — title, artist, album art, and play/pause/next/previous for players that report to Windows (music apps and the browser tab that is playing).
  • Made for a mount — fullscreen, landscape-locked, screen stays awake, with a screen-saver that guards against burn-in on an always-on phone.

How it works

Deckster is three cooperating parts: the phone (a touch page, shown either by a small native Android app or by any browser), the link between phone and PC (a USB cable or Wi-Fi), and the agent on the PC (which does the real work against Windows audio). The phone never talks to Windows directly — it only ever talks to the agent, which keeps the phone simple and the PC in control.

Figure 1 — The four layers. Every arrow is two-way: your touches travel down to Windows, and the resulting state streams back up so the phone always mirrors the PC. The phone only ever talks to the agent, never to Windows directly.

The phone

On Android you install a small native app; on an iPhone or anything else you just open a web address. Either way you are looking at the same touch page — the native app is a thin shell that hosts that page and adds a few conveniences (finding the PC over USB, scanning a pairing code, remembering the connection). The page keeps a live connection open to the agent so it updates the instant something changes on the PC.

The agent

The agent is the brain. It serves the touch page, holds the live connection to the phone, and turns each instruction into a real Windows action — set this app's volume, mute the microphone, switch the output device, skip the track. It also watches Windows and pushes changes back to the phone, so if you change the volume on the PC the phone's dial moves too.

The link

Two ways to connect, covered next. The short version: USB is the most private (traffic never touches your network) and lowest-latency; Wi-Fi is wireless and works for any phone with a browser.

Connecting your phone

Pick the path that suits your phone. On Android the app supports both and can hand a live session from USB over to Wi-Fi if you unplug the cable; on an iPhone you use Wi-Fi in Safari.

Figure 2 — The two connection paths. USB keeps the whole conversation inside the cable (nothing reaches your network); Wi-Fi carries it over your home network, optionally encrypted with a pinned certificate so there is no warning and nothing to install on the phone.

Android — use the app (recommended)

  1. USB: enable Developer Options → USB debugging on the phone, plug it into the PC, and open Deckster — it finds the PC over USB automatically. The first time, enter the 6-digit pairing code shown on the PC.
  2. Wi-Fi: with phone and PC on the same network, choose Wi-Fi, scan the QR code (or type the PC's address), and pair with the code. Turn on the secure connection for an encrypted link.

iPhone / iPad — use the browser

  1. On the PC, switch the connection to Wi-Fi.
  2. On the iPhone, scan the QR code with the Camera app — it opens Safari and pairs in one step. (Or open the address and type the 6-digit code.)
  3. Tap Share → Add to Home Screen for a fullscreen, app-like icon.

The security model

The design goal is simple: only a phone you have deliberately paired can control your PC, and even then only through the agent. Deckster runs as your normal user account — it never needs administrator rights.

Figure 3 — Pairing once, then token-gated forever. The one-time code proves physical access to the PC; it issues a per-device token that every future command must present. The PC stores only a hashed copy of the token, so the file on disk cannot be replayed as a credential.

  • Pairing proves presence. The one-time code is shown on the PC, so only someone at the PC can pair a device.
  • Every command needs a valid token. Unknown devices only ever see the pairing screen.
  • USB is off-network by default. In the wired mode the agent is not exposed to the network at all.
  • Encryption is available on Wi-Fi. The agent can serve an encrypted link; the Android app pins the certificate's fingerprint, so the link is warning-free with nothing to install.
  • The settings page is local-only. It answers only to the PC itself, never to a phone on the network.

For developers — forking & extending

Deckster is free software under the GNU General Public License version 3.0 (GPLv3). The codebase is small and deliberately layered so you can read one part without the others. This section is enough to find your way around and build it.

Build it

PC agent — run from source (Windows, Python 3.10+)

pip install -r requirements.txt
python -m agent.main

PC agent — package to a single .exe

pip install pyinstaller
pyinstaller build/streamcontrol.spec --distpath dist --workpath build/_work --noconfirm

Android app — build the APK (needs the Android SDK and a Java Development Kit 17+)

cd android
./gradlew :app:assembleDebug

Extending it

Because the phone only speaks to the agent over one live connection, adding a control is usually two small changes: teach the agent a new instruction (validate it, act on Windows, include the result in the state it streams out) and add the button to the touch page that sends it. The UI never touches Windows, so you can prototype against the built-in mock audio backend with no hardware in the loop.

Where to start reading

Open the agent's web/WebSocket server to see the message types the phone and PC exchange, then the audio engine to see how an instruction becomes a Windows call. The touch page's app.js shows the other side of the same conversation.
